# Map the reference layer to RDF (ref_specialty, ref_codes, ref_rules)

## Overview
Track 3 of the KG build. Maps `core.ref_specialty`, `core.ref_codes`, and `core.ref_rules`
to RDF via a new R2RML mapping, following `kg/mappings/referral_state.rml.ttl`'s pattern.
182 triples materialised, verified against Postgres. Two ambiguities were found and resolved
with the user before writing anything, recorded in this track's `decisions.md`.

## Two things resolved before implementation
1. **Target graph.** namespaces.md §5's own named-graph table assigns `ref_specialty`/
   `ref_codes`/`ref_rules` to `…/kg/graph/reference` ("build only") — not
   `…/kg/graph/inputs`. Confirmed with the user: use `…/kg/graph/reference`, per the doc's
   own table.
2. **ConceptScheme IRI for the 7 non-CPC code_tables.** `eat:CPCScheme` is already a named
   `eat:` vocabulary term, not something a mapping mints. namespaces.md §4 has no template
   for the scheme node itself for the other 7 tables. Confirmed with the user:
   `eatd:scheme/{code_table}`.

## Functional Requirements
1. `kg/mappings/reference_layer.rml.ttl` with 9 `rr:TriplesMap`s: `SpecialtyMap`,
   `CPCConceptMap`, `CPCSeverityRankMap`, `CPCCrtDaysMap`, `TriageOutcomeConceptMap`,
   `OtherRefCodesConceptMap`, `RefCodesSchemeMap`, `RuleMap`, `RuleThresholdDaysMap` — all
   with a constant `rr:graphMap` of `…/kg/graph/reference`.
2. `kg/mappings/reference_layer.ini` (git-ignored, not committed, matching
   `referral_state.ini`'s precedent): `output_file: out/reference_layer.nq`,
   `output_format: N-QUADS`.
3. `ontology.md` §6 amended: the 4th CPC concept (code 4, "Excluded") added to the worked
   example, with no `eat:severityRank`/`eat:crtDays`/`eat:outranks`, and a note on the
   discrepancy from the original three-concept example.
4. No `eat:outranks` triples generated by the mapping — those three triples are already
   static content in `eat.ttl`/`ontology.md` §6; regenerating them would duplicate them
   across the ontology and reference graphs for no benefit.
5. No new SHACL shapes (explicitly out of scope per the task).

## Non-Functional Requirements
- Never sorts or infers ordering from `code_value` (R6).
- Every `ref_codes` value becomes a `skos:Concept` IRI, never a bare literal (R6).
- NULLs filtered in SQL, in separate triples maps (`severity_rank`, `crt_days`,
  `threshold_days`), exactly as `referral_state.rml.ttl` already does for `valid_to`.

## Acceptance Criteria
- `kg/mappings/reference_layer.rml.ttl` exists; materialised output matches every row count
  in the table above exactly.
- Zero occurrences of `"None"` in the materialised output.
- `pyshacl -s kg/shapes/structural.ttl -df auto <output>` → `Conforms: True`.
- `ontology.md` §6 documents all four CPC concepts.
- No file outside `kg/mappings/reference_layer.rml.ttl`, `ontology.md` §6, and this track's
  own directory is touched.

## Out of Scope
- SHACL shapes for `eat:Rule`/`eat:Specialty`/generic `skos:Concept`.
- `eat:outranks` generation.
- Loading into a persistent Oxigraph store (materialise-to-file only).
