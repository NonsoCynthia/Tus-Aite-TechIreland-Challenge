# How the Graph Was Built

The tech stack and what each piece is for, the five decisions taken before any triples were
written, and nine things the build disproved along the way.

Companion documents: [`GETTING_THE_GRAPH.md`](GETTING_THE_GRAPH.md) for setup,
[`../../conductor/kg/`](../../conductor/kg/) for the normative specification. The five
decisions are presented visually in [`design-review.pdf`](design-review.pdf).

---

## 1. The tech stack

Every choice below is either inherited from
[`../../conductor/tech-stack.md`](../../conductor/tech-stack.md) or recorded there as an
architecture decision.

### Standards

| | What it does here |
|---|---|
| **RDF / OWL** | The data model and the ontology. Classes, properties, domains, ranges |
| **R2RML** | The mapping language. Declares how a Postgres row becomes triples |
| **SPARQL 1.1** | Query. Also the language of the shared wait-counter fragment |
| **SHACL** | Constraints. What OWL cannot express — see §2, Decision 2 |

### Tools

| Tool | Version | What it does here |
|---|---|---|
| **Postgres** | (dataset) | Holds the source data, the Type-2 change-detection view, and the read-only loader role |
| **Morph-KGC** | 2.10.0 | Executes the R2RML mappings against Postgres and materialises N-Quads |
| **psycopg** (v3) | binary | The Postgres driver Morph-KGC uses |
| **SQLAlchemy** | ≥ 2.0 | Required by Morph-KGC. Below 2.0 there is no `postgresql+psycopg` dialect |
| **Oxigraph** | 0.5.11 | The triple store. SPARQL 1.1 Query, Update and Graph Store Protocol over HTTP |
| **pySHACL** | 0.31.0 | Validates the materialised graph against `shapes/structural.ttl` |
| **rdflib** | 7.2.1 | Parsing and serialisation, and the engine pySHACL runs on |
| **owlrl** | 7.1.4 | OWL-RL closure at build time. See §4.7 — it turns out to do nothing here |
| **pyoxigraph** | 0.3.22 (pinned) | In-process store used by `tests/test_wait_counters_sample.py` |
| **Conductor** | v1.6.0 | Claude Code plugin. Spec-driven development: one track per unit of work, each with a spec, a plan and its own decisions file |

### Vocabularies reused

| | Used for |
|---|---|
| **PROV-O** | The decision layer. `eat:cites` is `rdfs:subPropertyOf prov:used`; scores, decisions, rule checks and rationales are entities generated by activities associated with versioned agents |
| **SOSA** | Observations. `sosa:Observation`, `observedProperty`, `hasSimpleResult`, `resultTime`, `hasFeatureOfInterest` |
| **OWL-Time** | Suspension intervals. Required for `adjusted_wait_days` to be derivable at all |
| **SKOS** | All 8 code schemes from `ref_codes`, plus specialties and the CPC ordering |
| **QUDT** | Units, on the observable property rather than the reading |
| **SHACL** | Structural shapes and, later, rule constraints |
| **DCAT / VoID** | Dataset metadata, release tag, seed (provenance graph, not yet populated) |
| **SNOMED CT** | Referenced by `sct:` IRI only. The ontology is licensed and enormous; nothing is imported |

### Deliberately not used

**FHIR RDF.** No interoperability requirement in this challenge, and it would double every
class. Field names stay MDS-aligned so a FHIR mapping remains possible later.

**The SNOMED CT ontology.** Referenced, never imported.

**FOAF and `org:`.** No people or organisations are named in this dataset by design.

**Apache Jena Fuseki and RDF4J.** Both JVM services; Oxigraph speaks the same SPARQL 1.1
HTTP protocol, so the swap is a container and a URL rather than a rewrite
(`tech-stack.md` Decision 1).

**rdflib as the construction path.** The project originally specified graph construction
"client-side" with rdflib. Replaced by declarative R2RML (`tech-stack.md` Decision 4): the
mapping is a reviewable artifact that diffs in a pull request, which for a project whose
selling point is auditability is worth more than a loader script.

**OWL as the constraint language.** Replaced by SHACL (`tech-stack.md` Decision 5). See
Decision 2 below.

## 2. The five decisions

Each was taken before the loader was written, because each changes what triples exist.
Full reasoning is in [`../../conductor/kg/decisions.md`](../../conductor/kg/decisions.md);
this is the summary.

### 1. One `Referral`, one `ReferralState` per material change

`referral_daily` reproduces the file hospitals send the NTPF: the whole list, resubmitted
each cycle. A referral appears once per day for as long as it waits, and on most of those
days nothing changed.

**Decided.** Never-changing fields sit on `eat:Referral`. An `eat:ReferralState` is minted
only when a material field differs from the previous `as_of_date`, carrying `validFrom`
and `validTo`. The four wait counters are **derived at query time**, not stored.

Measured, not assumed: 70,022 rows collapse to 13,772 states over 5,200 referrals — 5,200
first appearances and 8,572 real transitions. The material fields are exactly ten:
`triage_status`, `triage_event_id`, `appointment_date`, `arrived_date`,
`last_cancellation_date`, `suspension_start_date`, `suspension_end_date`, `removal_date`,
`high_clinical_or_social_needs`, `specialty_hipe`. The wait counters are excluded on
purpose — they tick daily by construction and would mark every row changed.

`valid_to` is set to `removal_date` where a referral was removed, and absent otherwise. An
open interval asserts "still on the waiting list"; leaving a removed referral open would
make every CRT breach query silently count removed patients as still breaching.

**Cost:** "what did the system see on the 9th" becomes a range query rather than a lookup,
so a citation must name the state IRI, never the date alone.

### 2. SHACL, adopted from the start

OWL reasons under the open-world assumption. Declare that Urgent outranks Semi-Urgent,
then produce a ranking that ignores it, and OWL reports nothing — no statement said
positions must respect that order, so there is no contradiction to find. This is not a gap
in OWL: inference and validation are different jobs, and a rule check needs the second.

**Decided.** Structural shapes written alongside the mappings; `sh:sparql` rule
constraints once the coordinating agent produces its first ranking, because they need a
placement to target.

The deeper reason is that SHACL validation reports are themselves RDF —
`sh:ValidationReport`, `sh:focusNode`, `sh:sourceShape` — which converts almost directly
into `rule_checks` rows with the focus node as the citation.

### 3. A unit belongs to the measurement type

`qudt:hasUnit` on the observable property, declared once in the ontology — six triples
replacing six per observation across 12,000 of them. Cheaper than the option that was
supposed to be cheapest, and the more accurate claim: a unit is a property of what is
being measured, not of each measurement.

Only 6 of the 13 observation columns take a unit at all. `pain` is a rating, `news2` a
composite score, `avpu` a code, `mts_category` and `icts_category` colour codes. A NEWS2
of 5 is not 5 of anything.

### 4. No identifier, no `Person` node

A patient with no national identifier gets **no `eat:Person` node** — no placeholder IRI,
no blank node. Two classes: `eat:Patient` always exists, `eat:Person` only where an IHI
does, joined by the functional `eat:isRecordOf`.

A placeholder would assert that a person exists while being uncitable and uncomparable:
the appearance of national identity with none of its substance. Absence stays a query
result instead — **1,788 patients cannot be linked nationally**, which is the finding the
dataset exists to show and is what a national shared care record would fix.

### 5. Rationale text in the graph, in its own graph, write-once

Generated rationale lives in `…/kg/graph/rationale`, write-once, with an invariant nobody
breaks: no agent's SPARQL reads from it. The same discipline as `ground_truth`, for a
different reason — ground truth is withheld to prevent circularity, rationale is isolated
so generated prose is never mistaken for evidence.

Storing it is not optional: regenerate the sentence tomorrow and the text differs, so
without it you cannot answer "what was the clinician actually shown". The `prov:used`
citation set is the point — comparing what a rationale used against what it says is how
"the model cannot introduce unsupported facts" becomes a CI test rather than a claim.

*Not yet built.* This decision governs work the agents will do; nothing in this directory
produces rationales.

## 3. How it was built, in order

Twelve Conductor tracks, each in
[`../../conductor/tracks/`](../../conductor/tracks/) with its own spec, plan and decisions.
Sequential, because each depended on the last.

| # | Track | Produced |
|---|---|---|
| 1 | `complete-eat-ttl-owl` | `ontology/eat.ttl` from a five-term stub to the full TBox |
| 2 | `wait-counter-sparql-fragment` | **Blocked.** Found the ontology could not express referral dates |
| 3 | `add-missing-data-layer` | The missing datatype properties; moved `referredToService` to the state |
| 4 | `write-validate-queries-wait` | `queries/wait_counters.rq`, validated 473/473. Supersedes track 2 |
| 5 | `record-wait-counter-findings` | The `time:Interval` structure, three gotchas, the pyoxigraph pin |
| 6 | `complete-exclusions-dictionary-test` | Traced all 50 column-coverage misses to a documented reason |
| 7 | `map-reference-layer-rdf` | `mappings/reference_layer.rml.ttl` |
| 8 | `map-cancellation-events-suspension` | `mappings/events.rml.ttl` |
| 9 | `map-six-capacity-tables` | `mappings/capacity.rml.ttl` |
| 10 | `map-conditions-observations-rdf` | `mappings/clinical.rml.ttl` |
| 11 | `map-referral-daily-triage` | Extended `mappings/referral_state.rml.ttl`; added the graph map |
| 12 | `extend-structural-shapes-every` | 16 more node shapes, 19 in total |

The order was chosen so that the riskiest assumption was tested earliest. Track 4 exists
before any of the mapping tracks because Decision 1 rests entirely on `adjusted_wait_days`
being derivable in SPARQL, and four mapping tracks assuming otherwise would have been
expensive to unwind. Track 8 (events) ran before the other mappings for the same reason:
the wait-counter fragment depends on its interval structure, and a mismatch there fails
silently.

## 4. Nine things the build disproved

Each was an assumption in the specification, or in the tooling. Each was caught by
something trying to *use* what the previous step produced.

### 4.1 Morph-KGC materialises SQL NULLs as the string `"None"`

The first mapping produced 55,088 triples where 49,888 were expected. Every one of the
5,200 open-interval states had a `validTo` — carrying `"None"^^xsd:date`, an ill-typed
literal asserting that a live referral had left the waiting list.

**Fix:** nullable columns get their own triples map filtering `IS NOT NULL`. Applied
throughout all five mappings. `grep -c 'None'` is now a per-mapping check.

This is the single most consequential tooling finding, because `referral_daily` alone has
fourteen nullable columns and the failure is silent.

### 4.2 The ontology had relationships but almost no attributes

Track 2 tried to write the wait-counter fragment and could not: `eat:Referral` carried no
`referralDate` or `referralReceivedDate`. The gap was wider than two properties — the
property table had been derived from a boxes-and-arrows diagram, so object properties were
complete and datatype properties were almost entirely absent. The data layer could not
state a name, a date, a count or a flag about anything.

**Measured on the way:** `validFrom` cannot substitute for the missing dates. The first
`as_of_date` for a referral equals `referral_received_date` in only **317 of 5,200** cases
and equals `referral_date` never. `validFrom` marks when the extract first captured the
referral, not when it was made.

**Fix:** track 3 audited every data-layer class against its source table and added the
missing properties. Track 6 then built `tests/test_column_coverage.py`, which fails if any
source column has neither a property nor a documented exclusion — the check that would
have caught this the first time.

### 4.3 `sh:sparql` cannot see Turtle `@prefix` declarations

pySHACL failed with `Unknown namespace prefix : eat`. Prefixes used inside a `sh:select`
string must be declared with `sh:declare` on an `owl:Ontology` node and referenced with
`sh:prefixes`.

### 4.4 The wait-counter fragment was being validated against the wrong graph

The fragment contains no `GRAPH` clause, by design — it is spliced into a consuming query.
Its test loaded hand-built triples into Oxigraph's **default** graph, which happened to
match. When track 8 produced the first correctly graph-tagged mapping output, the fragment
silently matched nothing and `adjusted_wait_days` came back equal to the unadjusted wait,
with no error.

Left undetected, every CRT breach calculation for a suspended referral would have been
wrong. It surfaced only because that track was required to run the fragment against real
mapping output rather than hand-built triples.

**Fix:** the test now loads into the named input graph and wraps execution in
`GRAPH { … }`, and both scenarios — hand-built and real-mapping — are asserted.

### 4.5 Two IRI templates named columns that do not exist

`namespaces.md` templated `eat:BedStatus` on `{status_datetime}`; the column is
`snapshot_datetime`. Caught by track 9 checking against the live schema. `clinic_sessions`
had been explicitly flagged as unverified and turned out to be correct — the flag was not
tracking where the risk actually was.

### 4.6 "No triage event" is not a proxy for "awaiting triage"

The first draft of the wait-counter fragment derived `days_awaiting_triage` from the
absence of `eat:hasTriageEvent`. Measured against `core.referral_daily`: **13,117 rows**
with `triage_status = 'triaged'` have no linked `triage_events` row at all — their triage
predates the retained event history — yet their `days_awaiting_triage` is correctly NULL.

Roughly one triaged referral in five would have been counted as still awaiting triage.
`eat:triageStatus` is the correct source, and matched every one of 473 sampled rows.

### 4.7 OWL-RL closure produces nothing application-level

Running `owlrl` over the loaded graph yields 55 new triples after filtering: XSD datatypes
typed as `rdfs:Datatype`, `owl:Thing`/`owl:Nothing` axioms, annotation-property typing.
Not one mentions an `eat:`, `sosa:` or `prov:` term.

The three `eat:outranks` triples already form their own transitive closure — a three-element
chain has exactly three ordered pairs, and all three are asserted. No other axiom in the
ontology generates entailments. **No query depends on inference at this stage**, and the
build-time materialisation described in `tech-stack.md` Decision 5 is provision for a
richer ontology later, not something today's correctness rests on.

Two further findings from that run, both worth knowing before anyone repeats it: `owlrl`
generates ~109,000 reflexive `owl:sameAs` triples, including on literals; and it emits
triples with **literal subjects**, which are invalid RDF and cannot be serialised as
N-Triples. Filtering anything with a `Literal` subject is the reliable remedy.

### 4.8 Per-file SHACL validation gives false negatives

`eat:hasCondition`'s 1..n cardinality on `eat:Referral` failed every Referral node when
`referral_state.nq` was validated alone — not a data fault, but because conditions come
from `clinical.rml.ttl`, a different mapping. Validating the union of all five files
passes with the constraint in place.

**Consequence:** union validation is now the standard, recorded in `requirements.md` §7.
It takes roughly 20 minutes on the full profile and belongs at integration, not per track.

### 4.9 Two clinical columns are empty

`chiefcomplaint` is null for all 5,200 observation rows and `snomed_ct_id` for all 6,977
condition rows. Both are modelled — `eat:ReportedSymptom` covers chief complaint,
`eat:snomedCode` covers SNOMED — and both produce zero triples.

The urgency agent therefore has **no free-text presenting-complaint signal**, and no demo
may rest on SNOMED interoperability. By contrast, MTS 5,119 + ICTS 81 = 5,200 exactly:
every referral gets one triage instrument, ICTS for paediatric cases. That one is correct
by design.

### 4.10 `triage_status` has only two values, and one of them is almost absent

`core.referral_daily` contains exactly two statuses: `triaged` (70,012 rows) and
`awaiting_triage` (10). No `redirected`, `rejected` or `removed` status appears at
all, despite the NTPF specification allowing them.

Three consequences, none of them a data fault, all of them things a demo could be
built on by mistake:

- **`days_awaiting_triage` is derivable but barely exercised.** The branch of
  `queries/wait_counters.rq` that computes it fires on 10 rows in the whole
  profile. The sample validation found exactly one awaiting-triage case in 35
  referrals, which is consistent.
- **`RULE-TRIAGE-TURNAROUND` has almost nothing to fire on.** It is one of the
  five rules in `ref_rules`. A rule checker run against this profile will report
  it as passing while testing essentially nothing.
- **`DATASET_README.md` §10.3** describes referrals with no urgency category as
  the ones most likely to be forgotten, precisely because they have no timeframe
  to breach. That population is 10 rows here, so the graph can represent the
  case but cannot demonstrate it.

Separately and unrelated: 13,117 of the 70,012 `triaged` rows have no linked
`triage_events` row (§4.6). The two findings have different denominators and are
easily confused.

## 5. Known limitations

Each is on the record because a demo or an agent could otherwise be built on it.

**5.1 Cross-hospital linkage is not exercised.** Inherited from the dataset
(`HOW_THE_DATA_WAS_MADE.md` §5.1): 3,412 patients carry an identifier and none occurs at
more than one hospital, so every `eat:Person` node has exactly one `eat:Patient` pointing
at it. The structure is right; the data does not exercise it.
`eat:citesMultiListEvidence` will have nothing to cite.

**5.2 The removal-closing branch of `valid_to` is untested by data.** No referral in the
`full` profile has a `removal_date`, so all 5,200 final states are open. The `COALESCE`
that closes a removed referral is correct but never fires.

**5.3 The open-suspension branch of `adjusted_wait_days` is untested by data.** No
still-open suspension exists in the `full` profile. The rule — a suspension contributes its
whole span once closed, nothing while open — was reverse-engineered from the stored counts
and matches every sampled row, but the open case is implemented to the same rule without
data to confirm it.

**5.4 `recordCreationDate` is derived by a correlated `MIN()` subquery.** `core.referrals`
has no such column. The value was verified constant per referral, so the subquery is exact
today — but nothing enforces that, and a future profile where it varies would silently take
the earliest.

**5.5 Unit-on-property assumes one unit per measurement type forever.** Safe here because
the data is generated with one unit per column, and exactly the assumption that fails in
real hospital data — the dataset's own MIMIC cleaning found a Fahrenheit reading in the
Celsius column. Real ingestion would move units onto the observation.

**5.6 `sosa:hasSimpleResult` has no declared range**, because the datatype varies by
observed property. Nothing in the ontology enforces it; `shapes/structural.ttl` carries a
12-branch `sh:or` that does. A future ontology change must not assume the ontology is the
enforcement point.

**5.7 `sh:closed` is used on no shape.** Every class accumulates properties from more than
one independently-run mapping, so closing any of them risks a false negative from an
incomplete enumeration. `tests/test_column_coverage.py` catches missing properties;
nothing catches extra ones.

**5.8 The awaiting-triage population is 10 rows.** `triage_status` takes only two
values in the `full` profile, and `awaiting_triage` accounts for 0.014% of them.
The urgency agent's handling of untriaged referrals, and any rule check on triage
turnaround, are structurally supported but cannot be validated against this data.

## 6. What is verified, and how

| Claim | Verified by |
|---|---|
| Every source column is carried or explicitly excluded | `tests/test_column_coverage.py` |
| The loader cannot read the answer key | `tests/test_loader_isolation.sh` |
| The wait counters match the source data | `tests/test_wait_counters_sample.py` — 473/473 rows, against both hand-built and real mapping output |
| Every mapping's node counts match Postgres | Per-track, recorded in each track's spec |
| No `"None"` literals | `grep -c 'None'` per mapping, must be 0 |
| The graph conforms to 19 SHACL shapes | pySHACL against the union of all five `.nq` files |
| No decision predicate in an input graph | `ASK` query in [`GETTING_THE_GRAPH.md`](GETTING_THE_GRAPH.md) §6 |
| No ground-truth triples anywhere | `SELECT` count in the same section |

What is **not** verified: that `sql/002_kg_loader_role.sql` works on a clean database. It
has only ever run where `kg_loader` already existed, so it always errors on `CREATE ROLE`.
Confirming it needs one `make reset` cycle.
